# HANDOFF（给接手 agent）

> 接手先读本文件；读完再决定读哪些细节。示例项目为虚构内容；默认目标 ≤150 行，完整性优先。
> 示例项目：一个用 Node + SQLite 的小型记单词 Web 应用。

## 0. 接手第一步

1) 读 `package.json`、`src/server.js`、`docs/architecture.md`；2) 确认分支和工作区；3) 跑 `npm test` 与 `npm run dev`。

## 1. 项目定位

- 项目一句话：个人记单词 Web 应用，服务需要离线复习和进度统计的学习者；不是在线课程平台。

## 2. 项目背景及发展

- 为什么存在：原先只有表格记录，无法稳定安排复习和追踪遗忘。
- 发展阶段：手工词表 → Node/SQLite 原型 → 加入每日复习和周统计；依据 `CHANGELOG.md`，参数仍待实测调整。

## 3. 当前状态与工作区

- 分支/提交：`main` / `v0.6.1`；工作区干净。
- 现在能跑：本地已用 `npm test` 验证 18 项；真实生产部署未在本轮验证。

## 4. 本次交接 agent 做了什么

- 检查了入口、数据库 schema、测试和部署脚本；补写本 HANDOFF；未改业务代码或数据库。

## 5. 为什么要做

- 项目目的：把词表、复习节奏和统计放进一个可重复运行的工具。
- 本次交接动机：让下一位 agent 先看到状态、数据边界和遗留风险，不必重新猜测部署方式。

## 6. 运行 / 测试 / 部署

- 安装：`npm ci`
- 运行：`npm run dev`（默认 3000）
- 测试：`npm test`
- 部署：`bash deploy.sh prod`（需要环境变量 `APP_KEY`，见 `.env.example`）

## 7. 完整项目目录及功能

| 路径 | 功能 |
|---|---|
| `src/server.js` | Express 入口和 HTTP 路由 |
| `src/review.js` | 每日复习调度逻辑 |
| `public/` | 原生 JS/CSS 前端 |
| `data/words.db` | 本地 SQLite 数据；部署前备份 |
| `tests/` | 单元与接口测试 |
| `deploy.sh` | 生产部署脚本 |
| `docs/architecture.md` | 架构和数据流说明 |

排除：`node_modules/`、`dist/`、测试缓存和 `.env`；它们是可重建依赖、构建产物或凭据，不属于交接目录清单。

## 8. 已知坑

- SQLite 在 Windows 上对文件锁敏感 → 并发写测试会失败 → 用 `--runInBand` 串行跑。
- 导入 CSV 必须 UTF-8 → GBK 文件会乱码 → 先在外部转码。
- `deploy.sh` 会重启 systemd 服务 → 本地测试别执行 → 先确认目标环境。

## 9. 不确定性 / 待确认

- 复习算法的遗忘曲线参数仍是经验值 → 以 `docs/experiments.md` 和基准测试为准。
- 移动端 375px 布局是否已修好未在本轮验证 → 发布前重新跑浏览器检查。
